# CLAUDE.md

ScrollCapture is a macOS 27 menu-bar agent (`LSUIElement`, Swift 6). **⌃⌥⌘S** screenshots the window under the mouse, scrolls it down with synthetic wheel events until it stops moving, stitches the frames and puts a PNG on the clipboard (or in the system screenshot folder when "Zapisuj do pliku" is on). Pressing the hotkey again, a mouse click or a key press (global `NSEvent` monitor, as in Shottr) stops a running capture and keeps what is stitched; a window that never scrolled ends with an error instead of a plain screenshot.

## Commands

The Xcode project is generated by XcodeGen and git-ignored; edit `project.yml`.

```bash
scripts/build.sh         # Debug build
scripts/run.sh           # build, kill the previous Debug instance, launch
scripts/install.sh       # Release build, replace and relaunch /Applications/ScrollCapture.app
scripts/test.sh          # offline tests (--adhoc: no "Local Self-Signed" certificate needed)
```

`xcodebuild` fails inside the Claude Code sandbox; run it with `dangerouslyDisableSandbox: true`. SourceKit errors before a build are noise.

## How it works

- `Sources/ScrollCapturer.swift`: picks the topmost layer-0 window under the cursor (`CGWindowListCopyWindowInfo`, front-to-back), captures it with `SCScreenshotManager` (`desktopIndependentWindow` filter), waits until the hotkey's modifiers are released, parks the cursor off the window (Shottr's spot: main display's right edge, 100 pt down) so hover effects don't change frames, then per step moves the cursor back (posted mouse-moved events: after `CGWarpMouseCursorPosition` Safari ignored the scroll events), waits 80 ms, scrolls a third of the scroll area's height as a stream of 20 pt pixel-unit `CGEvent`s from a private-state source (one large synthetic delta moved Safari only a few rows), waits 350 ms, captures again. Two still steps in a row end the capture. A failed match is retried with up to 3 fresh captures (Shottr's `nilShifts` idea: videos, spinners, lazy-loaded blocks); after that the capture stops, keeps what is stitched and saves the offending pair as `~/Library/Caches/com.mirek.scrollcapture/{previous,failed}.png`. Each step is logged: `/usr/bin/log show --last 10m --info --predicate 'subsystem == "com.mirek.scrollcapture"'` (plain `log` is a zsh builtin).
- Every frame is cropped to the AX scroll area under the cursor (`AXUIElementCopyElementAtPosition`, walking up to `AXScrollArea`; Safari's page without toolbar and tabs; whole window when the app exposes none), then both sides are trimmed by the window's corner radius (transparent pixels in the bottom row, 48 px at 2× on macOS 27) but at least 16 pt and at most 32 pt (a translucent window has no opaque bottom row): the rounded bottom corners otherwise leave a notch at both edges of every appended slice, and the overlay scroller goes with it.
- `Sources/Stitcher.swift` (pure, tested): the first moving pair fixes the scrolling band (rows that changed), so static headers and footers are left out of matching. Each band row is hashed as 16 vertical strips, so a sticky sidebar, the overlay scroller or an animated ad spoils only its strips, not whole rows. Only strips that changed between the two frames are scored, so fixed wallpaper, a stuck sticky column and blank margins don't count (gry-online.pl scrolls under half its width); the shift is the `dy` (at most 1.25× the expected scroll) where most changed strips match (≥ 60 %), ties broken towards the expected distance. Under 2 % changed strips means no movement. Shift 0 = end of page.
- "Uruchamiaj przy logowaniu" registers the app with `SMAppService.mainApp` (as Glosso does). It registers the running copy, so turn it on in the `/Applications` build from `scripts/install.sh`, not in a Debug build.
- The hotkey is a Carbon `RegisterEventHotKey` (`GlobalHotkey` in `Sources/ScrollCaptureApp.swift`): no permission, swallows the chord. Tests are Swift Testing (`Tests/StitcherTests.swift`, synthetic frames).
- Permissions: Accessibility (posting events) and Screen Recording. Signed with the shared `Local Self-Signed` identity so TCC grants survive rebuilds.
- Icons (`Sources/Assets.xcassets`): Tabler `arrow-autofit-down` in white on a teal `#0E9F8E` squircle, plus a template menu-bar glyph — the same style as Glosso's icons.
- The user verifies the UI by hand; don't drive the app with Computer Use.

## Reference: how Shottr 1.9.3b does it (static evidence only)

From imports, ObjC/Swift metadata and strings of the stripped binary (`Shottr-1.9.3b.dmg`, not kept in the repo):
`ScrollCapturer` class (`grabScrolling(direction:method:then:)`, ivars `screenshotInterval`, `noShiftTimeout`, `lastShiftDetectedTime`, `shifts`, `nilShifts`, `stitchedScreenshot`), scrolling via `CGEventCreateScrollWheelEvent2` + `CGEventPost` (Accessibility required, "reverse direction" setting for MOS/Scroll Reverser users, speed slider, max-height limit), capture via `SCScreenshotManager` / `CGWindowListCreateImage` / `CGDisplayStream`. Shift detection: custom `findShift(shots:lastCapture:step:…)`, `shiftPixels(img:tpl:maxShift:)`, `shiftGradient(…)` template matching, plus a `VisionStitcher` using `VNTranslationalImageRegistrationRequest`; joining via `combine(shots:region:direction:stripeHeight:…)`, `overlayCompareSegment` and `overlayShiftStamp` fallbacks. Shottr stitches a user-selected area; this app uses the window under the cursor instead.

From disassembly of the installed Shottr 1.9.3 (arm64, `otool -tV`; constants read from `__DATA`): each step warps the cursor to the scroll point (`CGWarpMouseCursorPosition`) and hides it (`NSCursor.setHiddenUntilMouseMoves`), creates **one** pixel-unit event (`CGEventCreateScrollWheelEvent2(NULL, kCGScrollEventUnitPixel, 1, ±step, 0, 0)`, sign flipped by `scrollingReverseAutoscroll`), posts it to `kCGHIDEventTap` after `0.15 × interval` via one-shot `NSTimer`, then after another `0.15 × interval` parks the cursor at `(CGDisplayPixelsWide(main) − 2, 100)`. The next step fires after `0.25 × interval`. `scrollingSpeed` (default 2) indexes interval `[0.8, 0.2, 0.12, 0.1]` s and step `[100, 100, 100, 300]` pt; the step is capped at `floor(regionHeight / 3)`; `scrollingMax` defaults to 20000 px.

From Ghidra 12.2 pseudocode of the same binary (the auto path lives at 0x1000a2000–0x1000aa000): frames are per-step `CGWindowListCreateImage` captures; `CGDisplayStream` only probes the Screen Recording permission on macOS 13–14. Each step keeps a strip of `step + (h − step)/2` rows from the region's bottom, and `combine` stacks the strips by the commanded step with **no matching per step**. A crc32 of the central 70 % × 70 % equal to the previous step's ends the capture after one still step. Only then does `findShift` drop the last two strips and align the last full frame: a per-row horizontal-gradient profile (x from 15 % to 85 %), accepted only when best × 1.2 < 2nd and best × 1.4 < 6th, else a byte-level comparison. `grabScrollingManual` is a separate `VisionStitcher`: the user scrolls, a 0.3 s timer captures, Vision `ty` gives the shift (no confidence check), and 70 % of each new frame is drawn over the end. Not adopted here: per-step matching with ties towards the expected shift needs neither the crc nor the ratio test, and both would break pages with spinners or blank stretches.
